# 졸업 외 모호한 질문 검토

검토일: 2026-09-13. 로컬 인덱스로 `decide_mode()` → `run_mode_tools()`를
15개 질문에 실행하고, `service.py`의 짧은 질문 처리와 대조했다.
운영 API나 LLM 생성 응답을 검증한 결과는 아니다. 아래 표는 최초 검토 시점의
동작이며, 이후 적용 상태는 아래에 기록한다.

## 1단계 적용: 절차 질문과 일정 조회 분리

- 등록금 납부·분할납부 방법, 성적증명서 발급, 수강신청 방법은 정책 검색으로 연결한다.
- 공식 안내 페이지를 제공하며, 원문 절차의 상세 요약은 아직 추가하지 않았다.
- `수강신청 언제야?`, `성적열람 기간`, `등록금 납부 기간`은 일정 조회를 유지한다.
- 날짜와 방법을 함께 묻는 경우 이번 단계에서는 절차 안내를 우선한다.
- `fast` 엔진 지정 시에도 절차 질문은 일정 도구를 사용하지 않는다.
- 단위 테스트 `check_academic_procedure_routing.py`와 최종 답변/API 회귀 사례로 검증한다.
- 단독 질문의 목적 확인은 아래 2단계에서 적용했다.

## 2단계 적용: 단독 질문의 목적 확인

- `등록`·`등록금`, `성적`, `수강신청`과 중립적인 `알려줘`·`안내해 주세요` 표현은 선택 안내를 반환한다.
- 등록은 납부 방법·분할납부·납부 기간, 성적은 열람·이의신청·증명서 발급,
  수강신청은 신청 방법·기간·정정 방법으로 질문 예시를 나눈다.
- 구체적인 방법·기간·연락처 질문은 기존 경로로 처리하며, 후속 질문은 주제를 포함한 전체 예시로 입력하도록 안내한다.
- 확인 안내에는 URL·날짜·금액을 넣지 않는다. 캐시와 짧은 인사 처리보다 먼저 실행하며 기존 안전 필터는 유지한다.
- `check_academic_clarification.py`, 최종 답변 평가 및 API 회귀 사례에 검증을 추가했다.
- 장학금·기숙사·휴학의 개괄 안내는 아래 3단계에서 적용했다.

## 3단계 적용: 장학금·기숙사·휴학 안내

- 장학금 단독 질문은 교내·국가·교외 구분을 안내하며, 종류 없는 신청 조건 질문은 장학금 이름과 대상 학기를 묻는다.
- 기숙사 단독 질문은 입사·비용·시설·위치 예시를 안내한다. 비용·입사 조건 질문에는 이용 시기와 유형을 묻고, 금액을 추측하지 않는다.
- 휴학 단독 질문은 일반휴학·군휴학·휴학연기 예시를 제공한다. 종류 없는 절차 질문에는 종류·희망 학기를 확인한다.
- 종류·목적이 구체적인 질문은 기존 조회로 연결한다. 구체적 조건에 대한 본문 추출·최신 모집 공고 검증은 이번 단계의 구현 범위가 아니다.
- 검색에서 해당 공식 페이지를 찾은 경우만 본문과 버튼에 같은 URL을 넣는다. 다른 페이지나 홈페이지로 대체하지 않는다.
- `check_support_guidance.py`와 최종 답변/API 회귀 사례에 검증을 추가했다.

## 4단계 적용: 빠진 적용 조건만 확인

- 수강신청 일정은 연도·학기·학년·학생 유형, 등록 일정은 연도·학기·학생 유형,
  성적열람 일정은 연도·학기를 확인한다. 이미 입력한 조건은 다시 묻지 않는다.
- `전체`·`모든` 일정 요청과 방법·연락처·규정 질문은 이 개인별 조건 확인을 적용하지 않는다.
- 조건이 완성되면 일정 검색도 학기·학년·학생 유형으로 필터링한다. 일정 제목에
  해당 조건이 명시되지 않은 경우 날짜로 추측하지 않고 자료 확인 불가를 알린다.
- 일부 조건을 적은 장학금·기숙사·휴학 질문에는 빠진 연도·학기·유형·납부 여부만 묻는다.
  일반휴학 신청 방법처럼 시기 확인이 필요 없는 절차 안내는 유지한다.
- 장학금 이름의 입력 여부는 특정 제도 목록에 제한하지 않는다. 이름을 입력해도 실제 존재·자격·금액은 검색 근거로 확인하며, 교내·교외처럼 범주만 입력한 경우에는 이름을 묻는다.
- 장학금 질문의 공식 안내 후보에는 장학금 제목 동의어를 적용해 일반적인 신청 안내보다 우선한다.
- 수강신청 조건·자격·서류 질문은 공통 절차 의도 판정을 사용해 일정 확인으로 가로막지 않는다.
- 조건을 모두 입력했다고 지급액·비용·자격을 확정하지는 않는다. 구체적인 근거 조회는 기존 검색 경로를 사용한다.
- 후속 질문은 주제와 기존 조건을 함께 입력하도록 안내한다. 대화에서 조건을 자동 병합하는 기능은 포함하지 않는다.
- `check_query_conditions.py`, 최종 답변/API 회귀 사례 및 기존 RAG 평가로 검증한다.

## 5단계 적용: 교수 단독 질문의 목적 확인

- `교수`, `교수님`, 중립적인 `알려줘`·`안내해 주세요` 요청에는 연락처·연구실 위치·교수소개 선택 안내를 제공한다.
- 교수명이나 학과명과 목적을 함께 입력하도록 예시를 제공한다. 이름·학과·조회 목적이 명시된 질문과 기존 연구실 확인 질문은 기존 경로를 유지한다.
- 확인 안내는 검색·LLM 호출 없이 반환하며 URL이나 실제 교수 연락처를 생성하지 않는다.
- 캐시와 짧은 인사 처리보다 먼저 실행하며 안전 필터는 그대로 유지한다.
- `check_professor_clarification.py`, 최종 답변/API 회귀 사례 및 CI에 검증을 추가했다.

| 우선순위 | 질문 | 현재 확인된 동작 | 개선 방향 |
| --- | --- | --- | --- |
| 1 | 등록 / 등록금 납부 방법 | `fast` → 등록 관련 여러 일정. 방법 질문에도 분할납부·졸업보류 등록 등이 섞임 | 등록금 납부·분할납부·등록 기간 구분. `방법`은 절차 검색 |
| 1 | 성적 / 성적증명서 발급 | `fast` → 성적입력·열람·확정 일정. 증명서 발급도 일정으로 처리 | 성적열람·이의신청·증명서 발급 구분. `발급`은 제증명 안내 |
| 1 | 수강신청 / 수강신청 방법 | `fast` → 수강신청·정정·계절학기 일정. 방법 질문에도 날짜만 안내 | 신청 방법·기간·정정 구분. 일정이면 학기·학년 조건 확인 |
| 2 | 장학금 / 장학금 신청 조건 | 교내외장학금 안내 페이지는 찾지만 조건 설명은 없음 | 개괄 안내와 교내/국가·교외 장학금 선택 제공. 자격·금액은 장학 종류와 학기 조건 필요 |
| 2 | 기숙사 / 기숙사비 | 기숙사 소개·안내 페이지 반환. 비용 질문도 동일 안내 | 입사 신청·비용·시설/위치 구분. 비용은 학기·입사 유형의 근거를 확인 |
| 2 | 휴학 / 휴학 신청 방법 | 휴학/휴학연기 페이지 반환. 절차 설명은 없음 | 개괄 안내 유지. 기간·서류·등록금 처리는 일반휴학/군휴학 등 유형 확인 |
| 기존 처리 유지 | 연락처 | 학과·부서 풀네임을 되물음 | 기관명이 명확한 질문을 과도하게 막지 않는 회귀 검증 |
| 기존 처리 유지 | 교수연구실이 어디야? | 교수명이나 학과명을 되물음 | 기존 clarification 경로 재사용 |
| 3 | 교수 | `oss`, 선택된 tool 없음. 서비스 코드상 두 글자 OSS 입력은 일반 인사로 처리 | 연락처·연구실·교수소개 중 목적 확인 |

## 먼저 고칠 부분

`LLM/OSS/modes.py`의 `looks_like_schedule()`은 `등록`, `성적`, `수강`이
포함되면 일정으로 분류한다. `decide_mode()`도 이를 정책 분류보다 먼저 적용한다.
따라서 명확한 `방법`, `발급` 질문까지 일정으로 빠진다. 이는 모호한 질문에 대한
되묻기만 추가해서 해결할 수 없는 분류 우선순위 문제다.

1. `방법/절차/발급/조건`과 `언제/일정/기간`의 구체적 의도를 먼저 구분한다.
2. `등록`, `성적`, `수강신청`처럼 목적이 없는 단독 질문에는 짧은 선택 안내를 제공한다.
3. `장학금`, `기숙사`, `휴학`은 개괄 안내가 유용하므로 안내와 선택지를 함께 제공한다.
4. 학기·학년·학생 유형에 따라 답이 바뀌는 경우에만 추가 조건을 묻는다.

정규식에 모호한 단어를 계속 추가하기보다는 질문 주제, 구체적 의도, 필요한 조건,
안내 문구를 분리한 규칙 목록을 두는 편이 적절하다. 구체적 질문은 되묻기를 통과해
바로 처리해야 하며, 다음 입력만으로도 검색되도록 `등록금 납부 방법` 같은 예시를 제공한다.

## 다음 변경의 검증 기준

- `등록금 납부 방법`, `성적증명서 발급`, `수강신청 방법`은 일정 목록으로 답하지 않는다.
- `수강신청 언제야?`, `성적열람 기간`은 일정 조회를 유지한다.
- 넓은 질문에서 특정 장학제도·휴학 유형·학기를 임의로 가정하지 않는다.
- 되묻는 응답은 근거 없는 금액·날짜·조건을 포함하지 않는다.
- 개괄 안내의 본문과 버튼 URL은 같은 자료를 가리킨다.
- 기존 교수연구실·학과 연락처 clarification은 유지한다.

검토에서 발견된 미수정 동작을 현재의 정답으로 고정하는 테스트는 추가하지 않았다.
현재 최종 답변 골든 사례에는 관련 공식 안내가 확인된 휴학·장학금·기숙사 개괄 질문과
기존 연락처·교수연구실 되묻기를 포함했다.
